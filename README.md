# 九爺，我想給您養老

宮廷主題的實體活動互動系統，分**主持人端**與**玩家端**。
所有資料 100% 記錄在 **Google Sheet**：每開一場（一個日期）就在試算表裡長出當天專屬的分頁，
當天的玩家、威望值、勢力值與每一筆調配紀錄都寫在裡面。

目前為**可實際運行的雛形**：完整流程已打通並通過端到端測試，遊戲階段與資源種類皆為設定檔驅動，方便繼續長出後續玩法。

## 快速開始

```bash
npm install
npm run dev          # http://localhost:3000
```

**不需要任何設定就能跑。** 沒偵測到 Google 憑證時會自動切到「記憶體模式」，
流程完全一樣，只是資料存在記憶體、重啟就清空——很適合先把玩法試順再接上 Sheet。
首頁最下方會顯示目前是哪一種模式。

其他指令：

```bash
npm run typecheck    # TypeScript 檢查
npm test             # 日期解析單元測試
npm run build        # 正式建置
npm start            # 跑正式版
```

## 接上 Google Sheet（正式模式）

### 1. 建立試算表

新開一份 Google 試算表，從網址取得 ID：

```
https://docs.google.com/spreadsheets/d/【這一段是 ID】/edit
```

分頁**不用手動建**，系統第一次用到時會自己開好並寫上表頭。

### 2. 建立服務帳號

1. 進 [Google Cloud Console](https://console.cloud.google.com/) → 建立或選擇一個專案
2. 「API 和服務」→ 啟用 **Google Sheets API**
3. 「憑證」→ 建立憑證 → **服務帳號**
4. 進入該服務帳號 → 「金鑰」→ 新增金鑰 → **JSON** → 下載

### 3. 把試算表分享給服務帳號

打開剛下載的 JSON，找到 `client_email`（長得像 `xxx@yyy.iam.gserviceaccount.com`），
回到試算表按「共用」，把這個信箱加進去並給**編輯者**權限。

> 這步最常被忘記。沒分享的話 API 會回 403。

### 4. 設定環境變數

```bash
cp .env.example .env.local
```

填入 `GOOGLE_SHEETS_SPREADSHEET_ID`，並用三種方式之一提供憑證（詳見 `.env.example`）。
最省事的是把整包 JSON 貼進 `GOOGLE_SERVICE_ACCOUNT_JSON`。

### 5. 驗證連線

```bash
npm run check:sheets
```

會依序檢查環境變數 → 服務帳號認證 → 試算表讀取 → 寫入權限，
並針對常見錯誤（沒分享、ID 打錯、金鑰失效）直接告訴你怎麼處理。
全部通過後重啟伺服器，首頁下方會變成「Google Sheet（正式）」。

> 本專案已用真實試算表完整驗證過：開場、入場、發放、階段切換、
> 伺服器重啟後資料仍在，以及 25 筆併發發放的正確性。

## 試算表長什麼樣

系統會自動維護三種分頁：

**`場次總表`** — 所有場次的索引

| 場次代碼 | 場次名稱 | 狀態 | 目前階段 | 主持通行碼 | 建立時間 | 更新時間 |
|---|---|---|---|---|---|---|
| 2026-08-16 | 週六下午場 | open | round1 | 9999 | … | … |

**`2026-08-16_玩家`** — 當天的玩家與目前餘額

| 玩家代碼 | 暱稱 | 通行碼 | 陣營 | 威望值 | 勢力值 | 狀態 | 加入時間 | 更新時間 |
|---|---|---|---|---|---|---|---|---|
| P7Q46HM | 六姨太 | 6113 | | 10 | 7 | active | … | … |

**`2026-08-16_紀錄`** — 當天的流水帳，只新增不覆寫

| 時間 | 類型 | 玩家代碼 | 玩家暱稱 | 資源 | 變動 | 變動後 | 事由 | 操作者 |
|---|---|---|---|---|---|---|---|---|
| … | grant | P7Q46HM | 六姨太 | 威望值 | 10 | 10 | 完成入府考驗 | 主持人 |

主持人可以直接在試算表上手動改數字，最慢 15 秒（`SESSION_CACHE_TTL_MS`）會反映到畫面上。

## 使用流程

**主持人**：首頁 →「我是主持人」→ 輸入日期＋自訂通行碼 → 開場
→ 進主持台後把日期唸給玩家 → 點選玩家 → 按 `+10` 之類的按鈕發放
→ 需要時切換階段、暫停或結束場次。

同一個按鈕也能回到已開的場次：日期與通行碼對得上就直接進主持台。

**玩家**：首頁 →「我是玩家」→ 輸入主持人給的日期 → 取個稱號入場
→ 之後畫面每 3 秒自動更新，隨時看到自己的威望值、勢力值與排名。

日期輸入很寬鬆，`2026-08-16`、`2026/8/16`、`20260816`、`8/16` 都會對到同一場。
查不到就顯示「無此場次」。

## 技術架構

| 層 | 選用 | 理由 |
|---|---|---|
| 框架 | Next.js 16（App Router）+ React 19 + TypeScript | 前後端同一個專案，玩家用手機瀏覽器就能開，不必裝 App |
| 樣式 | Tailwind CSS v4 | 古風配色集中在 `globals.css` 的 CSS 變數，好整批換 |
| 資料庫 | Google Sheets API（服務帳號） | 依需求，100% 記錄在試算表 |
| 即時更新 | HTTP 輪詢（主持台 2.5 秒 / 玩家 3 秒） | 見下方說明 |

### 兩個關鍵設計

**1. 伺服器端快取，解決 Sheets API 配額**

Google Sheets API 的讀取限制大約是每分鐘 60 次。如果 20 個玩家每 3 秒輪詢一次，
就是每分鐘 400 次讀取，**必爆配額**。

所以場次狀態在伺服器記憶體裡保留一份快照：

- 玩家輪詢一律打在記憶體上 → 不論幾個玩家，對 Sheets 的讀取次數都固定
- 寫入（發放資源）即時寫回 Sheet，同時更新快照
- 快照超過 15 秒會在背景重新拉一次，順便撈到主持人手動改表的內容

因此「100% 用 Google Sheet 記錄」與「幾十個玩家同時看即時數字」可以並存。

**2. 每場次一把鎖，避免算錯數字**

發放資源是「讀餘額 → 加減 → 寫回」，主持人手快連按時可能交錯執行而少算。
`src/lib/game.ts` 的 `withLock()` 把同一場次的存取串成一條鏈。

**關鍵是：背景快取刷新也必須走這條鏈。** 否則會發生
「刷新讀到舊餘額 → 有人發放並寫回 → 刷新結果蓋掉快取 → 下一筆從舊值往上加」，
中間那筆就憑空消失了。這個 bug 在真實 Google Sheets 環境下實測時被抓到（帳本出現重複餘額），
已修正並用 25 筆併發驗證：帳本是完整的 1…25 序列，無重複也無遺漏。

> 這把鎖在單一 Node process 內有效。若之後要部署到會自動水平擴展的環境
> （多個實例同時服務），需要改成外部鎖，或固定跑單一實例。

**3. 批次寫入，讓全體發放維持在一秒內**

逐筆呼叫 Sheets API 每位玩家約 0.7 秒 —— 20 人全體發放要主持人在桌邊乾等 15 秒。
改成「餘額一次 `values.batchUpdate`、紀錄一次 `values.append`」後，
不論幾人都只有兩次往返：**實測 20 人從 15 秒降到 0.82 秒**。

**4. 配額重試**

Sheets API 有「每分鐘 60 次寫入」限制，主持人連續快速操作會撞到 429。
`src/lib/store/sheets.ts` 的 `withRetry()` 以指數退避重試，讓短暫尖峰自己消化掉，
而不是把錯誤丟給主持人。實測 25 筆瞬間併發全部成功（耗時 11 秒，因退避而拉長，但沒有任何一筆失敗）。

## 要改遊戲內容，改這裡

幾乎所有玩法設定都集中在 **`src/lib/config.ts`**，不用動資料庫也不用動 API：

```ts
// 加第三種資源（例如「銀兩」）
export const RESOURCES = [
  { key: "prestige",  label: "威望值", short: "威望", accent: "--gold" },
  { key: "influence", label: "勢力值", short: "勢力", accent: "--jade" },
];

// 改遊戲階段：加關卡、改名稱、決定哪些階段還能讓玩家入場
export const STAGES = [
  { id: "checkin", label: "入府報到", hint: "玩家陸續加入", allowJoin: true },
  { id: "round1",  label: "第一回合", hint: "初探九爺府",   allowJoin: false },
  // …
];

// 主持台快捷按鈕的數值
export const QUICK_DELTAS = [1, 3, 5, 10, 20];
```

> 新增資源需要同步在 `src/lib/types.ts` 的 `ResourceKey` 加上對應的 key，
> 並在 `store/driver.ts` 的玩家欄位定義補一欄，TypeScript 會提示要改哪裡。

配色改 `src/app/globals.css` 最上面的 `@theme` 區塊。

## 測試

```bash
npm test                      # 日期解析（15 個案例）
npm run typecheck             # TypeScript 檢查
npm run check:sheets          # Google Sheet 連線診斷

# 全流程 UI 測試（需另外裝 playwright：npm i -D playwright）
npm run build && npm start &
BASE_URL=http://localhost:3000 node tests/ui-smoke.mjs
```

每次跑 UI 測試都會用一個隨機的未來日期當場次，所以可以重複執行。
測試留下的資料可以用下面的指令清掉：

```bash
npm run session:remove -- 2031-08-11
```

`session:remove` 會刪掉指定場次的兩個分頁與總表那一列，
只接受明確的 `YYYY-MM-DD`，不會誤刪其他分頁。日常清理舊場次也可以用。

`tests/ui-smoke.mjs` 會實際開瀏覽器走完：身分選擇 → 主持人開場 → 玩家「無此場次」
→ 玩家入場 → 主持人發放 → 玩家端即時更新 → 階段切換，並檢查有沒有主控台錯誤。

## 部署

### ⚠️ 不能用 GitHub Pages

GitHub Pages 只服務靜態檔案，**無法執行這個專案**：

- 專案有 9 個 API routes（`/api/sessions/…`），必須在伺服器上執行
- Google 服務帳號私鑰**必須留在伺服器端**。若改成純靜態、讓瀏覽器直接呼叫 Google API，
  等於把私鑰公開給每一位玩家——任何人都能竄改分數或刪掉整份試算表
- 伺服器端快取與寫入鎖活在 Node 程序記憶體中，沒有伺服器就沒有這兩者

同理，Netlify / Cloudflare Pages 的純靜態模式也不行。需要一個**能跑 Node 的環境**。

### 建議：Render（免費方案即可）

這個專案的鎖與快取都在單一 Node 程序內，最適合「一個長駐實例」的環境。

1. 到 [Render](https://render.com) → New → Blueprint → 指向這個 repo
2. 它會讀取 `render.yaml` 自動建立服務
3. 到服務的 Environment 分頁填入兩個變數：
   - `GOOGLE_SHEETS_SPREADSHEET_ID`
   - `GOOGLE_SERVICE_ACCOUNT_JSON`（整包 JSON，或 base64）
4. 部署完成後會得到一組網址，開場前先打開讓它醒著即可

> 免費方案閒置 15 分鐘會休眠，冷啟動約 50 秒。活動開始前先開一次就沒問題。

### 其他選項

| 平台 | 適合度 | 注意事項 |
|---|---|---|
| **Render / Railway / Fly.io** | ✅ 最佳 | 單一長駐實例，架構完全吻合。`Dockerfile` 也已備好 |
| **Vercel** | ⚠️ 可用但有代價 | Next.js 原生支援、部署最快，但 serverless 多實例各有各的快取，玩家可能看到數字忽高忽低。若要用，把 `SESSION_CACHE_TTL_MS` 降到 3000 讓實例間快速收斂 |
| **本機 + Cloudflare Tunnel** | ✅ 活動現場很實用 | 用筆電跑 `npm start`，開一條 tunnel 給手機連。零成本、零延遲，但依賴現場網路 |
| **GitHub Pages / 純靜態託管** | ❌ 不可行 | 見上方說明 |

目前 repo 只有 `claude/work-environment-check-6adtk7` 一個分支。多數平台預設會找 `main`，
請先把這個分支合併到 `main`（或在平台設定中指定要部署的分支）。

## 目前的限制

雛形階段刻意先簡化的部分，正式上線前建議處理：

- **身分驗證很陽春**：主持通行碼以明碼存在試算表，玩家身分存在瀏覽器 localStorage。
  正式版建議改成雜湊 + httpOnly cookie。
- **主持通行碼寫在試算表裡**：拿得到試算表的人就看得到。若要更嚴謹，改存環境變數或另一份權限更緊的表。
- **單一實例**：寫入鎖與快取都在記憶體，需固定跑一個實例（Render／Railway／自架都可以）。
  若要上 Vercel 這類會自動擴展的環境，得先把鎖改成外部實作。
- **一天一場**：場次代碼就是日期，同一天目前只能開一場。要一天多場的話，代碼規則要再擴充。
- **寫入配額**：Sheets API 每分鐘 60 次寫入。正常主持節奏（每分鐘數次發放）遠低於此，
  已有重試機制吸收尖峰；但若要做成「玩家自己觸發大量寫入」的玩法，就需要改成批次佇列。
